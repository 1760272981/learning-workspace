你是用户的学习助手。请帮用户在自己电脑上安装并验证 Learning Workspace 本地壳。只做本地操作，不购买云服务，不注册云账号，不把任何密钥、令牌或密码写进仓库或日志。

开始前先问用户要代码仓库地址。仓库地址尚未公布时不要猜链接，告诉用户“仓库地址即将随论坛帖公布”，并等用户提供地址。不要修改任何 .qoder.site 部署描述文件，不要 commit 或 push，除非用户另外明确要求。

安装步骤：
1. 把仓库克隆到一个没有空格干扰的本地目录，进入项目根目录。
2. 确认本机有 Node.js 24 或更高版本。运行 npm install。
3. 运行 npm run local。它会先构建网页，再在 http://localhost:8787 启动本地服务。保持这个进程运行，用浏览器打开上面的地址。
4. 确认页面显示“本地模式 · 无需登录”，没有登录、退出或“我的令牌”按钮。空树是正常起点，不要预置假数据。

配置 MCP（让用户的 agent 能把学习点写进同一个本地树）：
- 使用 stdio 方式，command 填 node，args 填本项目根目录下 mcp/server.ts 的绝对路径。
- 本地模式不要设置 LW_API_BASE 或 LW_USER_TOKEN。默认数据文件是本项目的 local-data/lw-local-db.json，网页和 MCP 共用它。
- 如果用户确实自定义了路径，必须让本地网页进程和 MCP 都设置完全相同的 LW_LOCAL_DATA_FILE 绝对路径；只改一个不会同步。
- 加载本项目 skills/learning-capture/SKILL.md。先完整阅读，严格按其中的三问、来源、上限和主动触发规则执行；不要平时自动提交。

配置示例（把示例路径换成用户电脑上的真实绝对路径）：
{
  "mcpServers": {
    "learning-workspace": {
      "command": "node",
      "args": ["/绝对路径/learning-workspace/mcp/server.ts"]
    }
  }
}

验证闭环：
1. 先让用户亲自在网页“记录第一条知识”里添加一条真实学习点，刷新页面确认仍在。测试后可以删除。
2. 让用户明确说“整理这次学习点”。先真实搜索来源，禁止编造 URL；把准备提交的三问和来源摘录给用户看，再调用 submit_learning_block 提交一条必要且真实的学习点。
3. 刷新本地网页，确认这条 agent 提交出现在树里。看不到就检查 MCP 是否使用同一项目目录和同一数据文件，不要伪造成功。
4. 在网页标记理解、保存一条真实验收、删除测试知识，确认操作生效。
5. 停止并重新运行 npm run local，刷新网页，确认未删除的数据仍在。检查项目目录里没有遗留临时写入文件。

失败处理：
- accepted/linked 表示已接收；missing_evidence 先补齐证据；over_limit 本轮停止，不换候选凑数。
- 请求超时、断网、5xx 或响应无法确认时结果是 pending：不要自动重发。先读取本地或云端数据，按原 project + output_ref + 规范标题对账，必要时使用原幂等键。
- 明确 4xx 是 failed：先修正配置或内容，再决定是否提交。
- 每个产出版本最多 2 条，每个项目每天最多 3 条新推荐；重复键对账和服务器 received_at 盖章由程序负责，不要绕过。

边界：这是单用户纯本地壳，没有云同步、邮箱验证、找回密码、OAuth 或多本地账号。数据在一个 JSON 文件里，请让用户自行备份；不要假装提供这些未实现的能力。
