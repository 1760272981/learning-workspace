## 一、自我介绍

〈学校 / 专业 / 年级；团队 1–3 人姓名与分工；赛道：StudyHack 学习科研〉
我们是〈…〉，平时用 AI 辅助做课程项目和个人项目。这次想解决"用 AI 学东西，但学完不会判断、验收"的问题。

## 二、你的作品是什么（一句话）

Learning Workspace 是一个给"用 AI 做项目的大学生"的学习工作台：把每一次 AI 产出用「三问」拆成可验收的知识，长成一棵可标记、可回顾、可验收的知识树。

## 三、为什么做

- 真实痛点：AI 给的答案看完就忘，下次仍不会判断它对不对、能不能用；"读懂了"不等于"会验收"。
- 想法来源：把学习的单位从"知识点"换成"一次具体判断/验收"。每条知识必须回答三问——现在要判断什么、产出里有什么证据、学完能亲自做什么验证动作；答不出就不进树。
- 取舍：宁可本轮推荐为零，不凑数；每个产出版本最多 2 条、每项目每天最多 3 条，优先误判后果大、马上要用的。

## 四、怎么用（5 步，评委照着即可打开用起来）

1. 打开作品链接（**无需登录**）：https://learning-workspace-v5d3qx7uw3a.qoder.zone
2. 看到示例知识树（带"演示数据"标签，明确是示例）；点任一果实查看它的三问与真实来源。
3. 点「＋ 记录知识」，填标题 + 三问 + 至少一条真实来源，提交入树（缺证据会被拦下并提示补哪项）。
4. 在果实详情点「我理解了 / 暂时跳过」，并写一条验收记录保存；树上出现对应徽标。
5. 用搜索 / 分支 / 状态筛选与排序回顾；删除可撤销；刷新后数据仍在（浏览器本地保存）。

## 五、用 Qoder 做出来的过程（哪几步交给它、我改了什么）

交给 Qoder 的：
- 前端整体实现与多轮重做：React+Vite+Tailwind 的"消消乐式藤条知识树"（纯 SVG 样条）、详情面板、提交表单、响应式与无障碍、统一艺术方向。
- 数据层与规则单一来源：`shared/model.ts`（三问校验、四态返回、每产出 2 条/每天 3 条上限、幂等、概念与应用分离），Web 与 MCP 共用。
- 本地 MCP 提交工具 `submit_learning_block` + 主动触发 Skill `learning-capture`（平时编码不打断）。
- 工程兜底：TypeScript 全量类型检查、git 基线、21 项自测、12 例验收评估（含两个换新会话的真实闭环）。
- 部署：Qoder Sites 打包上传 → 发布 → 设公开 → 未登录可访问验证（HTTP + 无 cookie 浏览器上下文）。
- 浏览器 QA：桌面 / 390px 移动、创建→入树→验收→删除撤销→筛选排序→刷新持久化，0 控制台报错。

我（负责人）改/拍板的：
- 产品红线："必要，不是什么都塞"；以判断/验收为中心；演示数据必须明确标注。
- 三问字段与上限数值；"已会就跳过、缺证据就问一个具体问题"的交互。
- 艺术方向与树的形态取舍（否掉多版方案，选定藤条果实）；不擅自补未要求的功能。
- 逐轮验收：每版 UI 与闭环由我在真实浏览器确认后才进入下一步。
